# Получатель записал пачку, отправитель потерял подтверждение

[Дополнительный тест для изменяемого источника](cursor_test.py) использует журнал с монотонным номером изменения. После потери подтверждения приходит новая ревизия задним числом. Курсор продолжает чтение по номеру, поэтому одинаковая дата у 51 документа и старая бизнес-дата у новой ревизии не теряют записи. Запуск из корня: `python crm/cursor_test.py`. Такая гарантия требует журнала, который источник действительно сохраняет; один фильтр по дате её не обеспечивает.

В наборе 53 документа. Получатель успевает записать первые 50, затем отправитель повторяет их и доставляет оставшиеся три. Проверка сравнивает состав и ревизии документов. Конфликтующий дубль откатывает пачку.

Из корня репозитория:

```console
python crm/batch_replay.py
```

Порядок источника здесь фиксирован. Реальный HTTP-сервис 1С и конкурирующие изменения справочника в модель не входят.
