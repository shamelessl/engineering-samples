# Почему в отчёте отдельно показаны пропущенный вызов и нарушение контракта

Объект проверки здесь вымышленный: локальный редактор, у которого интерфейс запросил счётчик и название документа. В таблице приведён весь вход из первого теста.

| Метод | Ожидание | Наблюдение | Что можно сказать разработчику |
| --- | --- | --- | --- |
| document.count | Целое число | 2 | Тип результата совпал в этом вызове. |
| document.title | Строка | null | Потребитель не может вывести длину строки. Уточнить контракт для пустого документа, затем согласовать проверку на стороне клиента. |
| view.zoom | Целое число | Вызов отсутствует в журнале | Нужен сценарий смены масштаба. Пока метод остаётся непроверенным. |
| view.ready | Нет описания | true | Уточнить назначение события и включить его в схему, если это поддерживаемая часть API. |

При повторной проверке нужен именно сценарий с пустым документом и журнал обеих сторон для этого вызова. Совпадение имён в сборке само по себе ничего не говорит о типе результата. Этот отчёт относится к приложенному тесту с вымышленными именами; сведения о приложении заказчика в него не включены.
